# Dear Passengers 深度调研与第二版差距清单

核验时间：2026-10-04，Asia/Shanghai。研究对象是 FLEXUS 的 Steam App 4534960。已查官方官网、Steam 商店与新闻、开发者/版主讨论、FLEXUS YouTube 频道，并在 Google Chrome 实际暂停检查预告关键帧。本文不把第三方攻略写成官方规格，不改游戏代码。

## 结论

现有版本已经具备可玩的浏览器航班任务，但与官方宣传的主要差距是 **角色表演、触手可及的第一人称动作、精细客舱、飞行与物理相互影响**。继续增加静态面板、航线名字和倒计时不会自动缩小这些差距。建议先做一段接近宣传质感、系统可相互作用的完整航班，再扩大内容。

截至本次核验，Steam 仍显示未发售；没有看到公开 Demo 下载或公开 Playtest 入口。10 月 2 日官方问答只明确计划发行前封闭测试。商店仍写 2026，最新问答却未给可承诺的月份/年份，应表述为「商店窗口 2026，具体日期与公开 Demo 时间未定」。这意味着目前能验证宣传所示表现与已确认功能，不能声称掌握原版完整任务、数值、地图和操作。

## 最新已确认范围

S1 明确有单人及在线合作；玩家要在出发前权衡乘客/货物报酬与风险，驾驶、服务并处理互相升级的事故。天气与飞机动作会影响松动物体和乘客。

S2 的新增信息可压缩为：当前最多 4 人，通过好友/房间码加入；随机匹配待定；无固定职业，存在近距离语音。飞行操作简化但包含避障、离开驾驶位、撞机；水降未承诺。风险货物会产生实际后果。航班间成长与外观定制计划存在，具体内容未揭晓。存档细节未知；暂不计划沙盒、难度分档、竞技或首发 Workshop；测试计划是闭测。引擎是 Unity，开发者将移动飞机内部物理与角色表现列为难点。

因此本站的三条航线、积分公式、具体升级、自动驾驶、精确计时、独立银行/保险规则，均是重建版本设计。即使保留，也应按游戏自身规则打磨，不应冠以「官方完整还原」。

## 美术拆解

**角色。** 不是棱角低模：头身偏长胶囊、轮廓圆润，巨大的凸出白眼球配小瞳孔；眼皮、眉与嘴型产生喜悦、惊慌、不悦。机组是蓝/黄/红/绿纯色皮肤，白短袖、深色领带、肩章金条，紫蓝飞行帽、黑帽檐与金色帽带。乘客有肉色皮肤、不同发型、花衬衫、背心、牛仔服、老人及警察，不能只复制同一个微笑人形换颜色。皮肤平滑偏哑光，衣服有软体积与阴影，不是塑料球拼接高光。

**客舱。** 皇家蓝软包座椅，头枕和靠背分块、有接缝与压陷；奶油色背壳、棕色扶手、金属支脚、黑带黄扣。大圆角矩形舷窗有明显厚度；乳白壁面/灰色机身肋/深蓝行李架与地毯分层。过道两条浅灰线增加纵深。后舱有货笼、木箱、钢琴、彩色箱子、瓶罐和香蕉皮，形成生活密度。

**光照。** 白天冷色天光与暖色灯具混合，物体落地有接触阴影，表面粗糙度让座椅/金属/皮肤区分。暴风状态转暗蓝，警报和火焰在附近表面产生局部红橙色响应。宣传质感来自这些关系，不宜用全场统一蓝色/红色环境光代替。

**驾驶舱与外景。** 玻璃环绕、模拟圆仪表、绿色雷达、红绿按钮、双推杆、操纵盘、头顶飞机损伤示意屏；机身白/黄/蓝。可见林地地面机场、峡谷、云海、风雪机翼；这证明环境多样，尚不能确定最终地图数量。

### 实施依赖判断

先建立一致的飞机坐标与物理所有权，再扩展破坏、飞行和联网，可减少后续重写。美术可与物理基础并行：角色表情、蓝色双手、软包座椅和光照的投入最容易在下一轮截图中看到收益。第一阶段至少应让「手动系带 → 搬运风险货物 → 颠簸打翻未固定物体 → 处理新事故 → 驾驶降落 → 解释结算」连贯可玩。具体 3—5 分钟压缩时长是浏览器版本设计，不是官方事实。

网络、自由驾驶、刚体物理属于结构性差距，不能通过动画或 UI 宣称已完成。可以分阶段交付，但要在可玩页面准确写明当前模式。
