# Passenger Flight 浏览器验收

## 自动化范围与运行

`scripts/qa-passenger-flight.mjs` 使用真实浏览器操作可见 UI。它不调用游戏内部状态、不写入预设胜利存档、不添加生产测试接口。默认地址为 `http://localhost:3000/play/cabin-crisis/`，需先由正常开发/静态服务启动新版游戏。

```sh
node scripts/qa-passenger-flight.mjs
```

部署前应再对构建输出启动的静态服务运行。线上核验可以指定已授权的网址：

```sh
FLIGHT_QA_URL='https://dearpassengers.net/play/cabin-crisis/' node scripts/qa-passenger-flight.mjs
```

脚本首先使用项目已有依赖，找不到时使用 Codex 已装运行时中的 Playwright 与 pngjs。没有增加项目依赖，也不会自行安装任何软件。当前环境发现 Playwright 1.62.1；其默认 Chromium 1234 缺失，但本机已有 Chromium 1243，脚本会选择实际存在的浏览器。

可选环境变量：

| 变量 | 用途 |
|---|---|
| `FLIGHT_QA_URL` | 完整游戏页面 URL |
| `FLIGHT_QA_OUTPUT` | 截图和 `report.json` 输出目录；默认系统临时目录下按时间新建 |
| `FLIGHT_QA_BROWSER` | 已安装 Chromium 的可执行文件绝对路径 |
| `FLIGHT_QA_NODE_MODULES` | 已有 Playwright、pngjs 的 `node_modules` 目录 |
| `FLIGHT_QA_HEADED=1` | 显示浏览器窗口，方便人工复核 |
| `FLIGHT_QA_ONLY=pause` | 只执行出发菜单、登机、暂停/继续、运行时错误检查，便于定点复测 |

运行有界，结束关闭本次浏览器；没有自动下载安装。退出码 0 表示全部自动检查通过，1 表示存在失败。失败时查看 `report.json` 和相邻 PNG，不应通过降低阈值掩盖实际游戏问题。

## 必须另做的实际玩法验收

以下尚未由上述短流程自动验证，发布前应实际完成并记录证据：

1. **完整首航。** 从选货物/登机开始，走到乘客和设备前完成至少一次服务、固定行李、安全带和故障处理；工具可获得、拿错时提示可理解，任务完成条件与画面一致。
2. **空间与碰撞。** 前后穿过机舱和驾驶舱，不能穿座椅/舱壁；玩家不能在边缘卡死。距离过远和隔墙不能完成交互；交互提示目标应和画面准心一致。
3. **驾驶与危机。** 进入驾驶状态后操纵会影响飞机，离开后能继续乘务。颠簸、失火、货物风险应能被玩家察觉和处理；失败也有明确的结束和重新开始入口。
4. **结算与三条航线。** 完成一整趟并到达结算页；分数、收益、等级与任务一致。随后进入下一航线，确认路线、事件或难度确有变化。不能只靠菜单展示未实现内容。
5. **成长/保存。** 有足够货币后买一次升级，检查扣费一次、生效一次；余额不足不能购买。刷新页面后已完成航线/升级/货币保留；重新开始当前航班不重复发放结算奖励。
6. **恢复能力。** 航班中切走标签页，再回来；暂停菜单点返回出发页，再开新航班。相同任务不出现多个计时器/音轨，旧事件不泄漏到新局。
7. **中文整局。** 中文进入航班、暂停、故障提示、结算和升级均可读，不只翻译主菜单。英文按钮名称用于无障碍或脚本时，不能替代用户可见的中文文案。
8. **移动端实玩。** 竖屏和横屏均完成一次拿取、移动、交互、丢弃；触控视角与摇杆能同时工作，松手后停止移动，滑出按钮不会持续跑动。短自动流程只验证按钮与基本移动。
9. **性能与音频。** 在实际设备检查高低画质、静音/取消静音、全屏进入/退出；至少连续玩一完整航班，无持续性能劣化。软件渲染的无头 Chromium 不是真实移动 GPU 性能基准。
